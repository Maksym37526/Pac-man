# Requirements Traceability Matrix — Pac-Man

Every requirement extracted from the subject, mapped to an owner, a location in
the codebase and a verification method. This is the single checklist used before
submission and the evidence of scope control required by subject VIII.

**Rule of scope:** if a task does not map to a row in this matrix, it is not
built. Features of the original arcade game that the subject does not require
are out of scope until every MUST row below is DONE.

## Legend

| Column | Meaning |
|---|---|
| **T** | `MUST` = explicit requirement · `SHOULD` = recommended, not mandatory · `FREE` = subject explicitly leaves the choice to us |
| **Owner** | `A` = Core/Systems · `B` = UI/Presentation · `A+B` = joint |
| **Where** | module, file or artifact implementing it — filled in as work progresses |
| **Verify** | the concrete check performed before marking DONE |
| **St** | `TODO` · `WIP` · `DONE` |

**Role assignment:** A = `myaroshu` · B = `ilobov`
